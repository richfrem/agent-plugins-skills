# BL-2036: v1.4 — TDD Enforcement Gates, Git Worktree Isolation, and Agent Pipeline

**Priority:** Medium-High  
**Depends on:** v1.3 hardened control plane (`state_engine.py`, `sandbox_runner.py`) fully implemented and tested  
**Target plugin:** `exploration-cycle-plugin`  
**Spec sources:** GPT-5.5 v1.4 proposal + Opus MAF gap analysis (2026-05-30 review session)

---

## Why This Matters

The v1.3 control plane enforces *who can execute* (approvals, HMAC) and *what runs* (budget gates, CAS).  
It does not enforce *whether the work actually passed*. A subagent can call `commit_task_complete` after producing broken code — the database accepts it.

This backlog item moves TDD from "the agent was told to write tests" to "the database refuses completion without passing test evidence." It also adds filesystem isolation between parallel agents via Git worktrees so concurrent subagents cannot clobber each other's working trees.

## MAF Gap This Fills

Per Opus red-team analysis (2026-05-30): MAF v1.0 + AGT govern runtime behavior (policy, identity, privilege, SLOs, compliance) but have **no Output Verification Middleware** — no middleware that gates a workflow state transition on the agent's output actually working. This is a gap in MAF, LangGraph, CrewAI, and Google ADK.

The local pattern validates the concept. The productized form would be:
- `TDDComplianceMiddleware` — plugs into MAF's `.Use()` chain alongside `GovernancePolicyMiddleware`
- `WorktreeIsolationExecutor` — custom MAF `Executor` wrapping `AgentExecutor` with per-task Git worktrees
- `OutputVerificationProvider` — MAF `AIContextProvider` post-call hook that stores TDD report as review artifact

## Scope: Three New Tasks After v1.3 Task 11

### Task 12: TDD Enforcement Gate in `state_engine.py`

**New table:**
```sql
CREATE TABLE IF NOT EXISTS tdd_evidence (
    id TEXT PRIMARY KEY,
    task_id TEXT NOT NULL,
    test_path TEXT NOT NULL,
    target_path TEXT NOT NULL,
    test_sha256 TEXT NOT NULL,
    tests_passed BOOLEAN NOT NULL,
    test_count INTEGER DEFAULT 0,
    failure_count INTEGER DEFAULT 0,
    test_output TEXT DEFAULT NULL,  -- truncated to 2KB
    duration_seconds REAL DEFAULT 0.0,
    verified_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    created_by TEXT NOT NULL,
    FOREIGN KEY(task_id) REFERENCES tasks(id)
);
```

**New function `verify_tdd_compliance(component_name, target_dir) -> dict`:**
- Looks for `tests/test_{component_name}.py` relative to `target_dir`
- Runs `pytest` via subprocess, captures structured output
- Returns dict: `{test_file_exists, tests_passed, test_count, failure_count, test_output, duration_seconds, verified_at}`

**Modify `commit_task_complete` signature:**
```python
def commit_task_complete(conn, task_id, subagent_id, version, payload_hash,
                         tdd_report: dict | None = None) -> bool:
```
- Returns `False` (no CAS attempted) if `tdd_report is None`
- Returns `False` if `tdd_report["tests_passed"] is False`
- Returns `False` if `tdd_report["test_file_exists"] is False`

**Tests to write first (TDD the TDD gate):**
- `test_commit_rejects_without_tdd_report` — missing report → False
- `test_commit_rejects_failing_tdd_report` — failure_count > 0 → False
- `test_commit_accepts_passing_tdd_report` — all pass → True
- `test_verify_tdd_compliance_detects_missing_test` — no test file → test_file_exists=False
- `test_verify_tdd_compliance_runs_passing_tests` — real pytest execution → tests_passed=True

**Important implementation note (from Opus):**  
Run `pytest` inside the *caller* (sandbox_runner or dispatch), not inside `commit_task_complete`. The state engine should only verify that verification happened — not block on test execution. Pass the structured report dict as evidence. This keeps the database layer fast and test execution in the process boundary.

### Task 13: Git Worktree Lifecycle in `sandbox_runner.py`

**New table in state_engine.py:**
```sql
CREATE TABLE IF NOT EXISTS worktrees (
    id TEXT PRIMARY KEY,
    task_id TEXT NOT NULL,
    branch_name TEXT NOT NULL,
    worktree_path TEXT NOT NULL,
    status TEXT CHECK(status IN ('active', 'merged', 'conflict', 'orphaned')) DEFAULT 'active',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    merged_at TIMESTAMP DEFAULT NULL,
    cleaned_at TIMESTAMP DEFAULT NULL,
    FOREIGN KEY(task_id) REFERENCES tasks(id)
);
```

**New function `setup_agent_worktree(task_id, component_name, repo_root, base_ref="HEAD") -> tuple[str, str]`:**
```python
# Atomic branch creation — avoids race condition of separate `git branch` + `git worktree add`
subprocess.run(["git", "worktree", "add", "-b", branch_name, worktree_path, base_ref], ...)
```
- Branch name: `task/{task_id}-{component_name}-{timestamp}` (timestamp prevents collision)
- Worktree path: `{repo_root}/workspace/tasks/{task_id}_{component_name}`
- Raises `RuntimeError` loudly if allocation fails (non-zero returncode)

**New function `teardown_agent_worktree(worktree_path, branch_name, repo_root) -> None`:**
- Merges branch into current HEAD with `--no-ff`
- On conflict: runs `git merge --abort`, raises `RuntimeError` (preserves worktree for manual resolution)
- On success: `git worktree remove --force` then `git branch -d` (not `-D` — safe delete only)

**New function `cleanup_orphaned_worktrees(repo_root, idle_threshold_seconds=3600) -> list[str]`:**
- Scans `git worktree list --porcelain` for paths matching `workspace/tasks/`
- Removes worktrees idle > threshold (mtime-based)

**Tests (write failing first):**
- `test_setup_worktree_creates_isolated_directory` — path exists, appears in `git worktree list`
- `test_teardown_worktree_merges_and_cleans` — file created in worktree appears in main after teardown
- `test_teardown_preserves_on_merge_conflict` — conflict raises RuntimeError, worktree survives

### Task 14: End-to-End Pipeline `run_task_pipeline()`

**New function in `sandbox_runner.py`:**
```python
def run_task_pipeline(conn, task_id, subagent_id, repo_root,
                      build_fn=None, ttl_seconds=300) -> dict:
    """6-step pipeline: lease → worktree → build → TDD → CAS commit → merge/teardown"""
```

Steps:
1. `lease_task(conn, task_id, subagent_id, ttl_seconds)` — budget-gated
2. `setup_agent_worktree(task_id, component_name, repo_root)` — isolated workspace
3. `build_fn(worktree_path, component_name)` — caller provides the build logic
4. `verify_tdd_compliance(component_name, worktree_path)` — pytest gate
5. `commit_task_complete(conn, ..., tdd_report=report)` — CAS with TDD evidence
6. `teardown_agent_worktree(worktree_path, branch, repo_root)` — merge + cleanup

Returns: `{success, tdd_report, worktree_path, branch_name, error}`

**Integration test:**
- `test_full_pipeline_lease_to_teardown` — real git repo + SQLite, end-to-end green path

## Implementation Notes

- `sqlite3` is Python stdlib — no install needed
- `pytest` must be available in the execution environment: `pip install pytest`
- Worktrees require the project to be a git repository
- `verify_tdd_compliance` times out after 120s to prevent runaway test suites
- The `tdd_evidence` table stores reports for the improvement ledger; query it to understand which components have the most test failures
