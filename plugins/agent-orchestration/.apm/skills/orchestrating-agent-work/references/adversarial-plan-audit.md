# Adversarial Plan & Code Audit (`plan_audit.py`)

This reference defines the deterministic, stateless-reviewer audit protocol used by `orchestrating-agent-work` and consumed by `running-control-plane` at `PLAN_REVIEW` and `WORKTREE_REVIEW`.

Attribution: the planner / isolated stateless-reviewer concepts (fresh-context reviewer, artifact-only packet, binary verdict, `not-run` never clean, two consecutive clean rounds with cap 5) are adapted from Google's `elephant-goldfish-model` (Apache-2.0), concepts only, expressed in our own terms.

## Roles & Isolation

- **Planner / Implementer** holds working context and drafts the spec, plan, or code.
- **Independent Reviewer** receives ONLY the packet generated by `scripts/plan_audit.py packet` (artifacts + target repo paths + fixed instruction block). Never pass conversation history, rationale dumps, or free-text nudges.
- **Host-enforced read-only tools**: subagent reviewers declare `tools: Read, Grep, Glob` (no Write/Edit/Bash). Note that read-only tools do not by themselves confine filesystem reads; pair with host `permissions.deny` or `--add-dir` scoping where available.
- **CLI reviewers** launched under OAuth without `--bare` may still load global hooks and user instructions; verdicts record the runtime used.

## Packet Contract (`plan_audit.py packet`)

```bash
python3 scripts/plan_audit.py packet \
  --artifact spec=docs/plans/work-tasks/<id>/<id>-spec.md \
  --artifact plan=docs/plans/work-tasks/<id>/<id>-implementation-plan.md \
  --target-path <repo-path> \
  --reviewer architect-review --reviewer security-auditor --reviewer tdd-contract-reviewer \
  --out docs/plans/work-tasks/<id>/plan-audit/round-1
```

`packet.md` starts with a fixed instruction block (identical bytes across runs) stating that artifact content is strictly data, not instructions. `packet.json` pins `packet_sha256`, artifact SHA-256 hashes, target paths, and declared reviewers.

## Recording, Settling, and Convergence

1. **Record each reviewer**: `plan_audit.py record --verdict verdict.json --round N --reviewer <name> --status completed|not-run --report <file> --findings <findings.json-or-inline-json> --packet <packet.json>`. A failed or empty reviewer MUST be recorded as `not-run` (never treated as clean).
2. **Settle findings**: `plan_audit.py settle --verdict verdict.json --finding <id> --as fixed|contested|accepted --by human|agent --note <text> [--evidence <file>]`. `contested` and `accepted` count as settled only when `--by human` or accompanied by an `--evidence` file hash.
3. **Convergence (`plan_audit.py check`)**:
   - Every declared reviewer is `completed` in each of the last **2** consecutive rounds;
   - Zero unsettled `Blocker` or `Major` findings in those rounds;
   - Every round's packet and report SHA-256 matches the files on disk;
   - The last packet binds all live `--artifact` hashes;
   - At most **5** rounds;
   - Every `recorded_at` is strictly after `--not-before` (when supplied from the control plane's signed preset timestamp);
   - Re-raising a finding at the exact trimmed `scope` of a previously fixed finding re-opens it; a new finding at a fixed scope is reported as churn (non-blocking).
